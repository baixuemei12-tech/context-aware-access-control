  4. FILE ACCESS — how authorization works
================================================================================

  When you click "Request access", this is what happens:

  1.  Your browser context is collected automatically (IP, time, device, etc.)
  2.  The gateway resolves context scores:
        - L_trust:  IP/network trust level (0-1)
        - N_status: Network security score (0-1)
        - D_sec:    Device security score (0-1)
        - T_req:    Temporal factor (working hours = high, night = low)
  3.  Object risk O_risk is computed from file size, access count, upload age
  4.  The effective threshold P_eff is raised: P_eff = P_req * (1 + 0.2 * O_risk)
  5.  Access rules are checked (org requirement, max daily access, min trust)
  6.  The oracle submits the request to Fabric chaincode via HMAC-signed call
  7.  Chaincode computes:
        CE_score = [w1*L + w2*N + w3*D - delta*R_interaction] * T_req
        DT_score = (alpha*T_sub + beta*CE) * Phi(B_freq)
        F_auth:  PERMIT if R_sub >= S_level AND DT_score >= P_eff
  8.  If PERMIT: a streaming session opens and the file is delivered in chunks
      If DENY:  you see the reason (low trust, wrong role, bad network, etc.)

  Common DENY reasons:
    - "Insufficient role"     → your R_sub is below the file's S_level
    - "Insufficient trust"   → your DT_score is below P_eff
    - "Rule violation"       → org/min-trust/max-access rule not met
    - "Risk budget exhausted" → daily download limit reached for this file
    - "Account blocked"      → anomaly detected, account temporarily frozen

  5. FILE UPLOAD — publishing a file
================================================================================

  On the Dashboard, scroll down to "Publish a file":

  1.  Click "Choose File" and select a file from your device
  2.  Enter a brief description
  3.  Set the sensitivity level using the slider (0.1 = low, 1.0 = maximum)
      This determines S_level (1-5) and P_req (0.1-1.0) for access control
  4.  Optionally configure access rules:
      - "Require organization": only users from this org can access
      - "Max accesses/day": cap the number of daily access requests
      - "Min trust (T_sub)": only users with trust >= this value can access
  5.  Click "Upload to IPFS"

  Your file is:
    - Encrypted with AES-256-GCM (per-file key)
    - Uploaded to IPFS (off-chain encrypted storage)
    - Registered in the gateway with pending status

  An admin must APPROVE your file before anyone can request access to it.
  Check your "Files uploaded" section on the Profile page to see status.

  10. CONTEXT MODEL — what the system knows about you
================================================================================

  The system uses a 4-dimensional context model C = (C_S, C_E, C_R, C_O):

  C_S — SUBJECT (who you are)
    R_sub   Role level (1-5), set by admin. Determines which files you can see.
    T_sub   Dynamic trust (0-1). Evolves with good/bad sessions.
            T_sub(n+1) = T_sub(n) + 0.1 * (outcome - T_sub(n))
    B_freq  Access frequency. High frequency reduces Phi(B_freq).

  C_E — ENVIRONMENT (where/when/how you connect)
    L_trust   Location/IP trust. LAN/known networks score higher.
    N_status  Network security. HTTPS/encrypted = high, open WiFi = low.
    D_sec     Device security. Large screen + desktop + no touch = high.
              Small screen + mobile + touch = lower.
    T_req     Temporal factor. Working hours (8AM-10PM) = high.
              Night (3AM) = near-zero. Smooth cos² decay, not binary cutoff.

  C_R — RESOURCE (what you're accessing)
    S_level   Sensitivity class (1-5), set by uploader, approved by admin.
    P_req     Minimum DT_score required for access.
    Rules     Optional: require_org, max_daily_access, min_trust, require_2fa.

  C_O — OBJECT (file properties)
    Access count   How many times this file has been accessed.
    File size      Larger files = higher O_risk = higher effective threshold.
    Upload age     Recently uploaded files carry higher O_risk.

  All C_E values are collected AUTOMATICALLY from your browser.
  You don't need to enter anything — just log in and request access.

================================================================================
  11. ALGORITHMS — how decisions are made
================================================================================

  ALGORITHM 1 — Access Evaluation (on-chain, O(1)):

    Step 1: Compute context-environment score
      CE_score = [w1*L_trust + w2*N_status + w3*D_sec - delta*R_interaction] * T_req(t)

    Step 2: Compute dynamic trust score
      DT_score = (alpha*T_sub + beta*CE_score) * Phi(B_freq)
      where Phi(B_freq) = 1.0 if B_freq <= tau, else e^(-lambda*(B_freq-tau))

    Step 3: Compute effective threshold
      O_risk = 0.4*novelty + 0.3*sizeFactor + 0.3*ageFactor
      P_eff  = P_req * (1 + 0.2 * O_risk)

    Step 4: Decision
      F_auth: PERMIT if (R_sub >= S_level) AND (DT_score >= P_eff), else DENY

  ALGORITHM 2 — Continuous Revocation (RGCA):

    After PERMIT, the system continuously monitors your session:
    - Trust margin m = DT_score - P_eff determines your tier
    - Tier controls polling interval, streaming speed, and data budget
    - If your context degrades (VPN drops, device changes), the scheduler
      re-evaluates and may REVOKE access mid-download
    - CSRP: if another user on your /24 subnet gets revoked, YOUR margin
      gets penalized too (cluster risk propagation)

================================================================================
  12. RGCA STREAMING — how file delivery works
================================================================================

  When access is PERMITTED, the file is NOT sent all at once.
  Instead, it's streamed through the gateway with risk-graduated controls:

  +----------+----------+----------+----------+----------+----------+
  | Tier     | Margin   | Polling  | Chunk    | Chunk    | Max per  |
  |          |          | interval | delay    | size     | window   |
  +----------+----------+----------+----------+----------+----------+
  | HIGH     | m < 0.1  | 2 sec    | 1000 ms  | 500 B    | 512 KB   |
  | MEDIUM   | 0.1-0.3  | 3 sec    | 250 ms   | 500 B    | 2 MB     |
  | LOW      | m >= 0.3 | 4 sec    | 100 ms   | 500 B    | 4 MB     |
  +----------+----------+----------+----------+----------+----------+

  Text files: chunk delay as shown above
  Binary files: higher delays (500ms HIGH, 50ms MED, 0ms LOW) and larger
  chunks (2 KB, 4 KB, 8 KB respectively)

  What this means for you:
  - HIGH-RISK tier: file loads slowly, 2-second pauses between chunks
  - LOW-RISK tier:  file loads quickly, minimal delays
  - Tier can change mid-download if your context changes
  - If revoked mid-download, the stream stops immediately

  DAILY BUDGET:
  Each user has a daily download budget per file. If exceeded:
    - Soft limit: forced to HIGH-RISK tier (slow but still downloading)
    - Hard limit: access denied until next day (midnight reset)
    - Admin can manually reset your budget

  TRT-BOUNDED STREAMING (TRT-BL):
  The per-window delivery is bounded by a provable formula:
    L(m,S,T,n) = min(B_max, mu*(1+kappa*T_sub)*S^theta*(1+psi*n))
  This guarantees that even if your session is compromised, the attacker
  cannot exfiltrate more than B_max bytes before the next re-evaluation.

  13. SECURITY FEATURES — protection in depth
================================================================================

  YOUR ACCOUNT:
    BCrypt passwords        Cost factor 12 hashing. GPU-resistant.
    TOTP 2FA               RFC 6238, 6-digit codes, Google Authenticator.
    Math CAPTCHA            Self-hosted HMAC-signed challenges (no external deps).
    Email verification      QQ Mail SMTP with timed verification links.
    Password reset codes    Admin-issued, hashed, IP-bound, rate-limited.
    Session tokens          UUID-based, 24h TTL, activity tracking.

  THE SYSTEM:
    AES-256-GCM encryption  Every file encrypted before IPFS storage.
    HMAC oracle signing     Every gateway→oracle request HMAC-SHA256 signed.
    CAAR receipts           On-chain evidence of every access session.
    HMAC audit logs         Tamper detection — altered entries flagged on load.
    Anomaly detection       Burst/trust-jump/sensitivity-escalation detection.
    Rate limiting           Sliding window per IP.
    Security headers        CSP, X-Frame-Options DENY, CORP, COOP.
    Zero-trust deny         Any verification failure → DENY by default.

  NETWORK:
    Oracle bound to localhost Only the gateway can reach the oracle.
    IPFS bound to localhost   Only the gateway can read IPFS.
    Fabric: gRPC TLS          Mutual TLS between peers and orderer.
    Gateway: only public port All other services are internal.

  18. FAQ & TROUBLESHOOTING
================================================================================

  Q: Why is my access request DENIED?
  A: Check the Risk Inspector on the right side of the Dashboard.
     It shows your T_sub, D_sec, N_status, S_level, P_req, and margin.
     Common fixes:
       - Low trust (T_sub):  contact admin to increase your trust score
       - Wrong time:         T_req is near-zero at night (3-6 AM). Try during
                             working hours (8 AM - 10 PM China time)
       - Weak device:        use a desktop with a large screen
       - Untrusted network:  avoid public WiFi; use wired LAN or VPN

  Q: Why is my file download so slow?
  A: You're probably in HIGH-RISK tier (margin < 0.1). This means the
     system is being cautious because your trust/context scores are close
     to the threshold. As your T_sub increases from good sessions, you'll
     move to MEDIUM and then LOW tier with faster delivery.

  Q: Why did my download stop mid-way?
  A: The RGCA scheduler re-evaluated your session and detected a context
     change (e.g., your VPN dropped, your network changed, or another user
     on your subnet was revoked). Access can be revoked at any time during
     streaming — this is by design for continuous security.

  Q: How do I enable 2FA?
  A: Go to Profile → Security → Two-factor authentication → Enable.
     Scan the QR code with Google Authenticator or Authy, then enter the
     6-digit confirmation code. After that, every login requires TOTP.

  Q: I forgot my password. What do I do?
  A: On the Login page, click "Reset password with admin code". You need
     an 8-character reset code from the admin. Contact the admin via
     the Messages page to request one.

  Q: Why does the Overview page say "offline" or "demo"?
  A: The blockchain network or oracle may not be running on the server.
     If you're presenting, turn on Demo Mode for visual placeholders.
     If you need real access, contact the admin to start the server stack.

  Q: How do I get a higher role?
  A: Only the admin can change your R_sub. Use the Messages page to
     request a role change. Higher roles (4-5) can access more sensitive
     files but also carry more responsibility.

  Q: Can I access the site from my phone?
  A: Yes, the site is responsive. However, mobile devices typically get
     lower D_sec scores (smaller screen, touch input), which may result
     in higher RGCA tiers (slower downloads). For best results, use a
     desktop or laptop.

  Q: What is the "Defense" button?
  A: It opens a 6-step presentation guide that walks through the system
     architecture → context collection → access decision → scenario demo →
     admin evidence → user security posture. Useful for thesis defense
     prep or explaining the system to others.

  Q: Why is my uploaded file still "pending"?
  A: An admin must approve every uploaded file before it becomes accessible.
     The admin sets the final S_level and P_req during approval. Contact
     the admin via Messages if approval is taking too long.
